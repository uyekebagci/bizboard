# Çatı (BizBoard) — v2.2.0 Advanced Search Engine Spec

> **Doküman tipi:** Feature Spec — security-first
> **Hedef okuyucu:** Coder ajanı
> **Mimar:** System Architect
> **Versiyon:** 1.0
> **Tarih:** 2026-05-16
> **Bağımlılık:** v2.0.0 (Flyway baseline + Audit Log v2) prod'da olmalı.

---

## 1. Genel Bakış

Çatı'da çok sayıda finansal/operasyonel entity var (işletmeler, karşı firmalar, kendi firmalarım, işlemler, personel, borç/alacak, envanter, ekipman, araç, banka hesabı, kredi kartı, kredi, doküman, not). Şu an her modülde ayrı bir liste arama var; **global** ve **gelişmiş** bir arama yok.

Bu spec, **kullanıcının yetkisi olmayan hiçbir veriyi yanlışlıkla bile göremeyeceği**, **9 katmanlı savunma** ile inşa edilmiş bir advanced search engine'i tanımlar.

### 1.1 Hedefler

- **Cross-entity global arama** — tek kutudan tüm entity tipleri.
- **İleri seviye query syntax** — `field:value`, `>`, `<`, `..`, AND/OR/NOT, tarih anahtarları.
- **Faceted UI** — entity tipi, işletme, kategori, tarih aralığı, tutar aralığı filtreleri.
- **Güvenlik:** **veri sızıntısı = kritik bug**. Backend, defense-in-depth ile yetkisiz erişimi engelleyecek.
- **Performans:** P95 < 300 ms, 100k+ kayıt ölçeğinde.
- **Kaydedilmiş aramalar, autocomplete, recent searches.**

### 1.2 Kapsam Dışı (v2.2)

- Türkçe stemming sözlüğü (`simple` config + `unaccent` yeter; tam stem v2.5'e).
- Elasticsearch/OpenSearch eklemek (Postgres FTS Çatı ölçeğinde yeter).
- ML tabanlı semantik arama / vector embeddings.
- Sesli arama.

## 2. Threat Model (Güvenlik Modeli)

Aşağıdaki tehditlere karşı katmanlı savunma yapılır:

| # | Tehdit | Risk | Mitigation Layer |
|---|---|---|---|
| **T1** | Tenant veri sızıntısı (User A, İşletme B'nin verisini görür) | 🔴 Kritik | L1 (auth) + L2 (access resolve) + L3 (mandatory filter) + L4 (RLS) + L9 (tests) |
| **T2** | Hassas alan ifşası (VKN, IBAN, maaş, vergi numarası) | 🔴 Kritik | L8 (response masking) + module permission check |
| **T3** | Enumeration attack (rastgele query ile entity varlığı tespiti) | 🟠 Yüksek | L7 (rate limit) + L6 (audit + anomaly) + L3 (sıkı filter — non-matching count'lar sızmaz) |
| **T4** | DoS — pahalı query (ör. `%a%` üzerine 10M kayıt) | 🟠 Yüksek | Query timeout (5s), entity başına 50 row limit, FTS index zorunlu |
| **T5** | SQL injection / crafted query | 🔴 Kritik | Parser sadece allowlisted field/operator kabul eder; tüm sorgular **parametreli** (string interpolation YASAK); Spring Data JPA Criteria veya QueryDSL |
| **T6** | Timing-based leak (yetkili olmayan veriye erişimde süre farkı) | 🟡 Orta | Sabit-zaman comparison; sonuç sayısını dahi access-filtered hesapla |
| **T7** | Audit log boşluğu (kim ne aradı bilinmez) | 🟠 Yüksek | L6 — her search audit'lenir (query string, kullanıcı, sonuç sayısı, IP) |
| **T8** | Shared cache leakage (Redis cache başka kullanıcının sonuçlarını gösterir) | 🟠 Yüksek | Cache key'lere `user_id` zorunlu; cross-user cache hit imkansız |
| **T9** | Suggestion/autocomplete sızıntısı (yazarken yetkisiz entity adı görünür) | 🔴 Kritik | Suggestions de aynı access filter altında — istisna yok |

├───────────────────────────────────────────────────────────────┤

## 5. Query Syntax (Advanced)

### 5.1 Temel

- `kira` — title/description/name'de "kira" geçen tüm sonuçlar
- `"yıllık kira"` — tırnaklı çoklu kelime (exact phrase)
- Default operator: **AND** (boşluk = AND)

### 5.2 Boolean

- `kira AND aralık` — her ikisi de geçen
- `kira OR kira-bedeli` — biri yeterli
- `kira NOT kasa` — kira içeren ama kasa içermeyen
- Parantez: `(kira OR aidat) AND 2026`

### 5.3 Field-specific

| Field | Örnek | Açıklama |
|---|---|---|
| `tip:` | `tip:transaction tip:debt` | Entity tipi filtreler |
| `isletme:` | `isletme:"Veli Restoran"` | İşletme adı (kullanıcı erişim listesinde olmalı) |
| `kategori:` | `kategori:KIRA` | Kategori (entity tipine göre) |
| `tutar:` | `tutar:>5000`, `tutar:1000..5000` | Sayısal aralık |
| `tarih:` | `tarih:2026-01`, `tarih:son-hafta`, `tarih:2026-01..2026-03` | Tarih aralığı |
| `durum:` | `durum:odenmemis` | Status (debt için) |
| `vkn:` | `vkn:1234567890` | Yetki gerekli (yoksa 403 değil, eşleşme yok) |
| `iban:` | `iban:TR12...` | Yetki gerekli |
| `etiket:` | `etiket:acil` | Tag filter (tags v2.3+'a planlanırsa) |

### 5.4 Tarih Anahtar Kelimeleri (Türkçe)

- `bugun`, `dun`, `son-hafta`, `son-ay`, `son-yil`
- `bu-hafta`, `bu-ay`, `bu-yil`
- `gecen-hafta`, `gecen-ay`, `gecen-yil`

### 5.5 Parser

- Allowlisted field + operator listesi backend'de **enum** olarak tanımlı.
- Tanınmayan field → 400 Bad Request `"Bilinmeyen alan: xyz"`.
- Tüm değerler **parametreli sorguya bağlanır** — string interpolation yasak.
- Spring Data JPA `Specification` veya **QueryDSL** kullanılır (raw SQL'den uzak).
- Parser unit test seti zorunlu (50+ edge case).

## 6. Postgres Altyapı

### 6.1 Extensions

```sql
CREATE EXTENSION IF NOT EXISTS pg_trgm;     -- fuzzy match (typo tolerance)
CREATE EXTENSION IF NOT EXISTS unaccent;    -- ı/i, ç/c, ş/s normalize
CREATE EXTENSION IF NOT EXISTS pgcrypto;    -- zaten var (UUID)
```

### 6.2 tsvector + GIN

Her searchable entity için:

```sql
ALTER TABLE transaction ADD COLUMN search_vector tsvector;
CREATE INDEX idx_transaction_search ON transaction USING GIN(search_vector);

-- Trigger: search_vector'i güncel tutar
CREATE OR REPLACE FUNCTION transaction_search_trigger() RETURNS trigger AS $$
BEGIN
  NEW.search_vector :=
    setweight(to_tsvector('simple', unaccent(coalesce(NEW.description,''))), 'A') ||
    setweight(to_tsvector('simple', coalesce(NEW.category,'')), 'B');
  RETURN NEW;
END $$ LANGUAGE plpgsql;

CREATE TRIGGER transaction_search_update
BEFORE INSERT OR UPDATE ON transaction
FOR EACH ROW EXECUTE FUNCTION transaction_search_trigger();
```

Aynı pattern her entity için tekrarlanır (migration script otomatik üretebilir).

### 6.3 Trigram (Typo Tolerance)

Yüksek hacimli text alanlarda fuzzy match için:

```sql
CREATE INDEX idx_counterpart_name_trgm ON counterpart USING GIN(name gin_trgm_ops);
```

Query: `WHERE name % 'ahmt'` (yaklaşık match) — kullanıcı "Ahmet" yerine "Ahmt" yazsa bile bulur.

### 6.4 Ranking

```sql
SELECT id, description, ts_rank(search_vector, q) AS rank
FROM transaction
WHERE search_vector @@ q
  AND business_id = ANY(:accessible_business_ids)
ORDER BY rank DESC, created_at DESC
LIMIT 50;
```

**Çoklu kriterli skor** (uygulama katmanında re-rank):
- Exact match boost: ×2
- Prefix match boost: ×1.5
- FTS rank: baseline
- Recency boost: `1.0 / (1.0 + days_old / 365)`

## 7. Row-Level Security (RLS) — L4

Postgres RLS, **uygulama bug'ı olursa bile** veritabanı seviyesinde yetkisiz satırları gizler. Defense-in-depth.

### 7.1 RLS Aktivasyon

```sql
ALTER TABLE business ENABLE ROW LEVEL SECURITY;
ALTER TABLE transaction ENABLE ROW LEVEL SECURITY;
-- ... her searchable tablo
```

### 7.2 Policy Örneği

```sql
-- App tarafında her oturum için: SET LOCAL app.current_user_id = '<uuid>';
CREATE POLICY transaction_tenant_isolation ON transaction
  FOR SELECT
  USING (
    business_id = ANY(
      SELECT business_id
      FROM user_business_access
      WHERE user_id = current_setting('app.current_user_id')::uuid
    )
  );
```

### 7.3 ADMIN Bypass

```sql
CREATE POLICY transaction_admin_bypass ON transaction
  FOR ALL
  TO PUBLIC
  USING (
    EXISTS (
      SELECT 1 FROM app_user
      WHERE id = current_setting('app.current_user_id')::uuid
        AND role = 'ADMIN'
    )
  );
```

### 7.4 Spring Boot Integration

Her API isteğinde `@Transactional` öncesi:
```java
jdbcTemplate.execute("SET LOCAL app.current_user_id = '" + userId + "'");
```

Daha temiz yol: Hibernate `StatementInspector` veya AOP aspect ile otomatik enjeksiyon.

> ⚠️ **`SET LOCAL` çok kritik** — `LOCAL` olmazsa session-wide kalır ve connection pool'da başka kullanıcıya sızar.

### 7.5 Test

- RLS aktifken `SELECT *` direkt sorgu sadece o user'ın satırlarını döner.
- Connection pool'da reuse senaryosunda eski user_id leak etmediği test edilmeli.

## 8. Centralized SearchService — L5

```java
public interface SearchService {
    SearchResult search(UUID userId, ParsedQuery q, SearchOptions opts);
    List<Suggestion> suggest(UUID userId, String prefix, int limit);
}
```

**Kurallar:**
- Tüm search endpoint'leri **yalnızca** bu servisi çağırır.
- Controller'da ad-hoc `repository.findByX(...)` ile arama **yasak** (lint kuralı / code review gate).
- Servis içinde:
  1. Parse query (field/operator validation)
  2. Resolve accessible business_ids
  3. Per-entity strategy (`TransactionSearchStrategy`, vb.) — her biri kendi tsvector sorgusunu yapar
  4. Sonuçları merge + re-rank
  5. Apply field masking (L8)
  6. Audit log (L6)

### 8.1 Per-Entity Strategy

```java
public interface EntitySearchStrategy<T> {
    EntityType type();
    Page<SearchHit> search(ParsedQuery q, AccessContext ctx, Pageable page);
    Optional<Suggestion> suggest(String prefix, AccessContext ctx);
    SearchHit maskSensitive(SearchHit hit, Set<Permission> perms);
}
```

Yeni entity eklendiğinde tek bir strategy yazılır + `EntityType` enum'a eklenir.

### 9.1 Endpoint'ler

|---|---|---|
| `GET` | `/api/v2/search` | Ana arama — `q`, `types[]`, `businessIds[]`, `page`, `size`, `sort` |

## 13. Performans Bütçesi

| Metrik | Hedef | Strateji |

| P95 latency (search) | < 300 ms | GIN index zorunlu, query timeout 5s, entity başına 50 row limit |

## 14. Test Stratejisi (Güvenlik-odaklı)

### 14.1 Functional

- Parser unit testleri (50+ edge case: nested parens, escaped chars, invalid fields).
- Multi-entity search integration testleri.
- Ranking testi (beklenen sonuç ilk 3'te).

### 14.2 Güvenlik (ZORUNLU)

| Test | Beklenen davranış |
|---|---|
| **Cross-tenant leakage** — User A, İşletme B'ye atanmamış. Arama yapar | İşletme B'nin tek satırı dahi response'da YOK |
| **RLS bypass attempt** — App'te filter olmasa bile, doğrudan repo çağrısı | RLS satır vermez |
| **Sensitive field masking** — Permission yok | VKN/IBAN/maaş response'ta maskeli |
| **Field-based bypass attempt** — `vkn:1234567890` yetkisiz | Eşleşme döner, ama maskeli; tam VKN sızmaz |
| **Cache key isolation** — User A query cache'i, User B'de hit etmez | Her cache key user_id içerir |
| **Rate limit** — 31. istek 1 dakikada | 429 |
| **SQL injection** — `'; DROP TABLE business; --` query'de | Parser reddeder + audit log warning |
| **Timing attack** — Yetkisiz business_id ile spesifik query | Sabit zaman; constant response |
| **Connection pool leak** — Aynı connection 2. user'a verildiğinde | `SET LOCAL` reset, eski user_id'yi okumaz |

### 14.3 Yük Testi

- k6 ile 100 RPS sustained 5 dakika. P95 < 300ms, error < %0.1.

## 15. Migration Stratejisi

1. **Flyway V2_2_0__search_extensions.sql** — extensions, tsvector kolonları, GIN indexler, RLS policies.
2. **Backfill job** — Mevcut satırlar için search_vector hesapla (offline batch, ETL).
3. **Trigger aktivasyon** — backfill bitince trigger'lar aktif.
4. **Feature flag** — `feature.advanced-search.enabled=false` ile başlar; sandbox'ta test, sonra prod'da aç.
5. **Eski endpoint'leri deprecate et** — modül başına basit liste arama (`/businesses?q=`) hâlâ çalışır ama UI search'i v2.2'ye yönlendirir.
